# Project subscription bindings into channel topics

Saved subscriptions remain authoritative, while a platform adapter projects their diagnostic identity into a channel's description (Discord Channel Topic). One delimited managed block carries a compact channel binding, a digest of the sorted subscription-instance/revision set, and feed-family counts; this accommodates multiple feeds within Discord's topic limit while preserving administrator-authored text. Full configuration and revision evidence remain available through `/diag`, rather than being reconstructed from the digest.

Subscription changes remain saved if topic synchronization fails: synchronization is reported as pending/blocked, transient failures are retried asynchronously, and `/diag` observes without repairing. Removing the final subscription removes only the managed block. This accepts temporary divergence between stored configuration and platform metadata so a remote permission, capacity, or availability failure does not invalidate a local configuration change.

Manual edits/removal produce reported drift until the next subscription change or explicit administrator synchronization; already-pending transient retries resume after restart while preserving current administrator text. Adapters or destinations without topic capability retain their internal binding and working diagnostics and report synchronization as unsupported; they do not implicitly modify a parent resource. Existing subscriptions receive stable identities and an initial revision on adoption, with tracking start distinguished from any evidenced original creation date. Adoption does not trigger bulk topic writes: initialization waits for a subscription change or explicit administrator sync. See the [consolidated spec](../../.scratch/diag-overhaul/spec.md) for the complete behavior and acceptance criteria.
