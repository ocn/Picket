# Recover contract monitoring without deployment automation

The contract rollout will use a guarded Recovery Deployment to the sole production environment because the deployed ESI-progress query cannot become healthy and sweep-coupled terminal admission cannot drain the live backlog. Complete Retained Contract Manifests remain authoritative, while one single-consumer in-process Terminal Resolution Recovery loop reuses the existing PostgreSQL cases, public ESI client, persisted limiter, and durable delivery path. This deliberately adds no service, schema, worker pool, canary environment, traffic split, tuning variable, speculative page telemetry, automatic stop, automatic rollback, or automated remediation: the existing watchdog detects and reports regressions, subsequent rollout work stops, and production state changes only with operator direction. Historical Enrichment Repair remains separately gated by Production Verification and a fresh exact-count approval.
